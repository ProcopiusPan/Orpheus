# Orpheus 快速开始

Orpheus 是运行在 Codex 中的数学研究插件。它帮助 Codex 保存 Obsidian 可读的研究笔记，并把通过独立 AI 冷审的小结论保存为 Git Fact。

> [!important] 证据边界
> `AI_REVIEWED` 表示独立模型审查没有发现已知错误，不等于形式化证明或人工专家认证。重要结论仍应由使用者复核。

## 1. 安装前准备

当前交付包适用于 Windows。请先安装：

1. Codex 桌面版，并确认已经登录；
2. Git；
3. Python 3.13；
4. 可选：Obsidian，用于阅读研究笔记；
5. 可选：Zotero，用于管理参考文献。

打开 PowerShell，逐项检查：

```powershell
codex --version
git --version
py -3.13 --version
```

三条命令都能显示版本后再继续。

## 2. 安装插件

解压交付包，在解压目录空白处按住 `Shift` 并单击鼠标右键，选择“在终端中打开”。然后复制执行：

```powershell
$target = Join-Path $env:USERPROFILE "Orpheus"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\install_portable.ps1" -InstallPath $target
```

看到包含 `"status":"INSTALLED"` 和 `"plugin":"orpheus@personal"` 的结果即表示安装完成。关闭当前 Codex 任务，再新建任务，使 Codex 加载新插件。

如果需要把正式 Fact 备份到自己的 GitHub，请先创建一个**空的私有仓库**：不要初始化 README、许可证或 `.gitignore`。然后安装时使用：

```powershell
$target = Join-Path $env:USERPROFILE "Orpheus"
$remote = "https://github.com/你的账户/你的空仓库.git"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\install_portable.ps1" `
  -InstallPath $target `
  -RemoteUrl $remote `
  -GitName "你的姓名" `
  -GitEmail "你的提交邮箱"
```

安装器不会接收或保存 GitHub 密码、令牌。Git 的登录窗口由本机 Git Credential Manager 提供。配置 `origin` 后，每次 Fact 接纳都会尝试普通 push；Codex 应报告：

- `SYNCED`：已经上传；
- `REMOTE_PENDING`：本地 Fact 已接纳，但上传失败，稍后可重试；
- `NOT_CONFIGURED`：没有配置远端，只保存在本机。

## 3. 开始第一个研究问题

1. 在电脑上创建一个普通文件夹，例如 `数学研究`。这个文件夹可以同时保存多个问题。
2. 在 Codex 中选择该文件夹作为本地项目并新建任务。
3. 复制下面的提示词，把最后一段换成自己的问题：

```text
使用 Orpheus 研究这个数学问题。请自主拆分和推进，及时维护 Obsidian 可读的研究笔记；得到证明完整、边界明确、可独立引用的小结论时，提交为小 Fact 并启动独立冷审。请明确区分研究草稿、待审候选、已接纳 Fact 和外部文献。

问题：
在这里粘贴问题。
```

Orpheus 会在研究项目中维护：

- `Orpheus研究/`：问题索引、过程笔记、阶段结论和审查记录；
- `papers/`：文献信息、阅读入口和 sidecar；
- 安装目录中的 Git 仓库：候选、审查报告和正式 Fact。

普通研究笔记可以修改。正式 Fact 不应直接编辑；发现问题时让 Codex提交问题报告或新版本。

## 4. 文献与 Zotero

不使用 Zotero 也可以研究。需要系统管理文献时，安装并启动 Zotero，启用本地 API，然后告诉 Codex：

```text
请使用 Zotero 管理本问题的参考文献，并把实际使用的文献信息登记到当前项目的 papers 文件夹。正式引用前请核对原文和精确位置。
```

若使用 Zotero，全文可由 Zotero 主库管理；否则可直接在项目 `papers/` 保存合法取得的原文和阅读入口。详细规则见 [Zotero 适配与使用](Zotero适配与使用.md)。

## 5. 根据 Fact 写论文

插件内置 Fact 论文写作 Skill。指定活动稿件和此次范围，即可整理初稿、按新 Fact 增量更新，或只精修语言与可读性：

```text
使用 Orpheus 的 Fact 论文写作 Skill，根据已接纳 Fact、完整证明和计算附件更新这篇论文。目标稿件：填写文件路径；本次范围：填写章节或目标；语言与格式：填写要求。
```

写作沿用项目的稿件格式和构建方式。研究笔记继续保存在原位置，论文保存到指定稿件中。详细流程见 [Fact 论文写作 Skill](../plugins/orpheus/skills/fact-paper-writing/SKILL.md)。

## 6. 常见问题

### PowerShell 提示禁止运行脚本

使用上面的完整命令，其中已经包含 `-ExecutionPolicy Bypass`。它只对这一次 PowerShell 进程生效。

### 提示缺少 `codex`、`git` 或 `py`

对应软件尚未安装，或安装后没有重新打开终端。完成安装后关闭 PowerShell，再重新打开检查版本。

### GitHub 仓库不是空的

安装器不会覆盖已有远端历史。请新建真正的空仓库，或先不填写 `RemoteUrl`，安装完成后再自行配置远端。

### 安装目录已经非空

安装器不会覆盖现有数据。请选择新的空目录。不要手工覆盖已有 Orpheus 安装中的 `facts/`、`candidates/` 或 `reviews/`。

### 新任务中看不到 Orpheus

先关闭旧任务并新建任务。如果仍不可见，执行：

```powershell
codex plugin list
```

确认 `orpheus@personal` 显示为 `installed, enabled`。

## 6. 卸载

先卸载插件缓存：

```powershell
codex plugin remove orpheus@personal --json
```

然后根据需要删除个人插件源目录和 Orpheus 安装目录。删除安装目录会删除尚未上传的正式 Fact，请先确认 GitHub 同步状态或自行备份。研究项目中的 `Orpheus研究/` 与 `papers/` 不会被插件卸载自动删除。

升级时不要把新压缩包直接覆盖旧安装目录。先保留旧目录和 Git 历史，再按照新版说明迁移。
