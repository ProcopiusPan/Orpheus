# Orpheus 便携交付包

该交付包只包含通用源码、Skills、一次性 stdio MCP、GitHub Actions、空 Fact 目录模板和安装脚本。它不包含交付者仓库的 `.git` 历史、Fact、候选、审查、问题、事件、SQLite、凭据或本机绝对路径。

第一次安装请优先阅读[快速开始](快速开始.md)。本页保留并行试用、隔离测试、远端约束和升级边界等高级说明。

## 安装

在 Windows PowerShell 中从解压后的包目录运行：

```powershell
./scripts/install_portable.ps1 -InstallPath C:/Users/you/Orpheus
```

安装器要求目标目录不存在或为空，并在写入前检查 Git、Python、Codex CLI、个人 plugin 路径和 marketplace。它会创建 Python 3.13 虚拟环境，按 `requirements.lock.txt` 安装依赖，初始化 `main`，生成指向新目录的绝对 `.mcp.json`，并用官方 Codex CLI 建立个人 marketplace 后安装 `orpheus@personal`。个人目录默认是 Windows 用户目录，也可用 `-PersonalRoot` 指向隔离位置。

安装完成后，在 Codex 中选择实际研究使用的本地项目文件夹，并从该项目进入工作模式。Orpheus 会在项目根目录的共享 `papers/` 中维护项目级文献信息登记、sidecar 和用户手动添加特定文献的入口，在 `Orpheus研究/` 中维护多个数学问题的 Obsidian 笔记；安装目录继续单独保存候选、审查和 Fact。研究笔记和文献不会因为卸载插件而自动删除，也不会自动成为正式引用。若使用 Zotero，全文通常由 Zotero 主库保存；也可以直接在项目中保留合法取得的原文。

### Zotero

Zotero Desktop 由用户按需安装和更新。若已配置 Zotero 并启用 Local API，官方 Zotero Skill/helper 可读取本地书目、children、附件路径和已索引全文；未配置时可直接使用项目 `papers/` 和合法检索。Orpheus 的登记脚本只写明确指定项目的 `papers/`，不包含 Zotero 条目的新增、编辑、删除或 Connector 导入操作。详细流程见 [Zotero 适配与使用](Zotero适配与使用.md)。

登记 Zotero 文献时默认在项目 `papers/` 创建同卷硬链接，使用与选定附件相同的数据；若文件系统不允许硬链接，可明确选择不复制附件的路径引用。用户也可直接把特定原文放入 `papers/` 并创建 sidecar；`sync_workspace.py sync` 会自动生成完整性摘要，`check` 会检查纯路径引用、硬链接和手动原文加 sidecar，并报告实际内容变化。安装包测试使用假 HTTP，不会接触用户真实 Zotero 库。

要与已有开发版并行安装试用版，使用唯一的小写连字符名称，例如：

```powershell
./scripts/install_portable.ps1 -InstallPath C:/Users/you/Orpheus-trial -PluginName orpheus-trial
```

试用版使用独立项目目录、Fact 历史、Git 历史、plugin source、marketplace entry 和 Codex selector；安装器会保留已有 `orpheus` entry，并把试用版写成 `orpheus-trial@personal`。不传 `RemoteUrl` 时不会配置或连接远程仓库。

也可以接收一个空的远程 Git 仓库：

```powershell
./scripts/install_portable.ps1 -InstallPath C:/Users/you/Orpheus -RemoteUrl https://github.com/you/empty-repo.git -GitName "Your Name" -GitEmail "you@example.com"
```

`RemoteUrl` 只接受不含 userinfo、query、fragment 或凭据的 HTTPS/SSH URL。安装器先用 `git ls-remote --heads --tags` 检查远程；远程已有任何分支或标签就停止。推送只使用普通 `git push --set-upstream origin main`，不 force push，并且只在本地安装和 plugin 成功后执行。`GitName` 与 `GitEmail` 只写入新仓库的本地 Git 配置。

测试安装路径而不写文件：

```powershell
./scripts/install_portable.ps1 -InstallPath C:/tmp/orpheus-test -DryRun
```

测试复制、Git 初始化和 MCP 路径而不下载依赖或安装个人 plugin，可在隔离目录使用 `-SkipDependencyInstall -SkipPluginInstall -PersonalRoot C:/tmp/orpheus-personal`；这两个开关只用于离线测试，正式安装应省略。

## 卸载和升级边界

安装器不覆盖非空目录、个人 marketplace 中已有的同名插件或非空远程。升级应先在临时目录解压新包并运行测试，再由用户审查 Git diff 后手工迁移源码；不要让升级器覆盖 `facts/`、`candidates/`、`reviews/`、`requests/`、`issues/` 或 `incidents/`。卸载时由用户明确删除项目目录和个人 marketplace 中的 `orpheus` 条目；远程仓库、远程历史和用户研究数据不会由本包自动删除。

绿色 CI 和远程备份不等于禁止强推或禁用 workflow。分支保护、rulesets 和审查规则是否生效，必须根据实际 Git 主机、仓库权限和仓库配置检查并记录。
