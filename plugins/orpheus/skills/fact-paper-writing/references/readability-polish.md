# 写作后的可读性精修

目标是把已组织好的数学内容变成便于连续阅读的学术叙述，不以压缩篇幅为唯一目标。
这是初稿之后的独立工序；新 Fact 增补完成后也检查新段落与相邻过渡。
不修改正式 Fact，不因润色改变定理的假设、量词、比较映射或结论强度。

## 1. 清理防御性表达

识别反复出现的否定、免责和预先回应质疑的句子：例如连续强调“并不声称……”、
“不能据此……”、“这不是……”，或每个结果后机械附一段相同范围声明。
先判断该句承载什么信息，再决定删除、合并、改写或调整位置。

- 已由定理假设和结论充分限定的范围，不必在紧邻段落重复多遍。
- 优先正面说明得到什么，例如“在以下假设下，命题给出这类对象的统一估计”。
- 会导致真实误读的区别保留一次，放在首次相关位置或恰当的 remark 中；不要把
  每个潜在误解都变成正文主线。
- 未证明的关键桥接、条件性结论、有限输入范围、非规范选择、真正开放问题不可
  作为“防御性表达”删掉。将必要限制写成准确的数学条件，而非模糊免责声明。
- 不把承重限制一律移到 README 或附录：只读定理及其证明的读者也应能理解范围。

例如，多处重复“本结果不适用于所有情形”时，可以在命题中明确适用对象和假设，
在需要处解释这些条件的作用；涉及计算时，在方法说明中限定输入范围。
读者由这些具体条件理解结论，不必反复阅读相同的范围声明。

## 2. 工程语言改为数学学术语言

正文的主语应主要是数学对象、映射、方程、定理及其逻辑关系，而非研究流程状态。
区分计算数学所必需的算法术语与可移出正文的工程记录。

| 工作记录中的说法 | 按真实内容改写为 |
|---|---|
| 前置检查 PASS | 逐项说明已核实的数学条件及其依据 |
| 比较接口闭合／证明链打通 | 指出具体构造、所满足的性质及其在论证中的作用 |
| 全部矩阵逐项回归通过 | 在指定坐标对应下，两组微分矩阵相等 |
| 上轮缺口已修复 | 陈述新增引理以及它在当前证明中的用途 |
| 处理流水线完成 | 说明输入对象、构造步骤及得到的数学结果 |

这些不是词汇的一对一替换：只有相应数学事实确已成立，才使用右列陈述。
“程序返回成功”不能仅通过措辞变成“数学条件已证明”。
将候选编号、接纳日期、审查轮次、宿主重放、哈希、CLI、缓存和交付状态等移到
现有证据台账、验证记录或复现附录，除非它们确是论文方法的必要组成。
Fact 追溯可按项目约定保留为紧凑标记；读者应能不打开台账而读懂论证。
算法的输入、输出、有效性、复杂度、实现限制和可复现性仍需说明，不能为了
“去工程化”删除计算论文的科学方法信息。

## 3. 长段落按论证功能分段

按意义边界分，而不按固定字数、句数或 PDF 行数切分。常见断点包括：

- 目标或直觉之后，转入正式构造；
- 构造之后，转入所需性质的验证；
- 一个证明步骤完成，转入下一步或独立情形；
- 计算得到公式之后，转入解释或应用。

段首说明这一段的目的，必要时用一句过渡交代它如何接续前段。
避免一段同时引入多套模型、符号、引文和结论，也避免每句独立成段导致论证破碎。
不为改善分页而拆断量词、公式的变量说明或依赖同一前提的推导。

## 4. 高密度处补解释，不只拆段

检查读者是否知道这一构造为什么出现、公式中各项来自哪里，以及结果将用于什么。
可按实际需要补充：

- 构造前一两句动机，例如需要保留哪些结构或性质；
- 首次公式后的类型、次数、符号及各项来源说明；
- 中间推导或一个低维特例，使抽象结论可被检验；
- 模型比较的方向、是否保底层数据，以及为何这一步能接回原定义；
- 步骤结束时一句局部解释，指出已经完成的数学义务，不写研究进度总结。

解释必须来自已支持的定义和证明。新例子或新数学断言若需额外证明，先核对，
不能以“帮助理解”为由补造。避免空泛动机、重复定理和无信息的连接句。
读者负担来自概念并列时，可集中比较或延后局部工具；不要为补解释再引入更多术语。

## 5. 精修后的复查

对照修改前后确认假设、量词、符号、证明步骤、证据等级及未决边界没有丢失。
检查正文是否仍有重复范围声明、工程状态句、过长复合段落或无解释的密集公式。
沿目标读者的阅读顺序通读相邻段落，确认过渡自然而不是只在局部句子上顺畅。
LaTeX 修改后按项目流程编译并检查受影响页面；排版通过不等于可读性验收。
交付时简述做了哪类精修及是否改变数学内容，不把润色称为新证明或完整冷审。
