# 稿件组织、同步与验证

## 组织正文

先问论文的中心问题和主要输出是什么，再沿依赖顺序讲：
定义与模型 -> 必要桥接 -> 核心定理/算法 -> 有意义的例子。
这只是常用结构，不是所有论文的固定模板。

围绕一个数学对象使用一套主记号；模型比较交代输入、输出、方向和符号约定。
复杂概念若只承担局部计算，放在需要它的位置，不扩大为全文基础架构。
重要表格适合展示输入/输出、模型层级或假设差异，不用表格代替推导。
正式环境应包含足以独立阅读的假设与结论，证明说明关键等式和末层条件。
章节安排与当前写作阶段一致，工作稿、定稿和投稿材料按各自目标组织。

数学内容成稿后，按 [写作后可读性精修](readability-polish.md) 单独检查语言和段落。
证据边界仍需准确，但不必将审查与工程记录的措辞逐句带入学术正文。

## 同步范围

修改前读取本地约定，确认哪份是活动源码：
正文、书目、译稿、导读和冻结稿的维护范围由目标项目现有约定决定。
只同步当前项目要求的版本。
保留稳定 label 与更新标记；改变符号时搜索实际使用者，不机械替换同名其他数学对象。
新增内容后更新当前摘要、目录导航、书目、结果对照及当前任务中的受影响项。
历史日志追加记录，不改写历史页数、计数或旧验证摘要。

## LaTeX 与 PDF 检查

复用项目已有检查命令和构建入口；不新增未经必要性证明的工具链。
独立单文件 LaTeX 若当前环境有内置编译器/编辑器，使用其规定的编译和预览流程；
多文件论文则使用项目构建方式。不为编辑本身安装无关插件。

检查未定义引用/引文、重复标签、环境与控制字符、公式符号、表格、QED 和新段排版。
proof 环境自动给结束符时，不再手加方块。
渲染修改后的相关页面；大结构变化时覆盖全文。报告现存警告及其影响，
不要把非阻断旧警告伪装成此次新增错误，也不要忽略新内容溢出。

独立源码构建仅在项目要求、自包含性发生变化或交付需要时做：
从活动源码复制必要文件到干净目录，运行足够遍数使标签与引用稳定，
核对构建实际使用的输入文件，确认源包包含所需内容。按需要比较提取文本与图像，不要求 PDF 二进制相同。
页数相同不能代替内容比较，文本一致不能代替视觉查看。

如交付独立源包/Overleaf ZIP，验证实际导出包而非只编译工作区，
并遵守项目的编译次数和比对规则；当前修改未验证的新包不能称为已同步。
源码编辑后编译不可用时保存源码并说明未验证，不声称 PDF 已更新。

## 交付说明的证据层级

分别报告：
- 实际编辑了什么，以及未编辑的范围；
- 实际运行并通过的机械检查/编译/视觉查看；
- 哪些数学证明与运行是复用已接纳证据；
- 仍缺的证明、有效性假设或实现限制。

引用检查、编译通过、文件来源一致、AI 冷审和内核形式化是不同验收，
不能以一项替代其他项。保持结论与本次执行的真实范围一致。
