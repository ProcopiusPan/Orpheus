# 文献归类

新增、复用或阅读文献时，顺手维护 Zotero 集合，使人也能浏览和寻找文献。分类是可调整的导航信息；后续阅读发现不合适时可以直接修正，不需要候选、审批、冷审或专门复核。

## 日常维护

- 先复用现有集合和条目，按题名、摘要、已有阅读认识及实际用途归类。一篇文献可属于多个主题和项目；不通过重复导入实现多重归属。
- 没有合适结构时，可按阅读入口、研究项目、学科主题和待核对组织；名称、层级由用户项目决定，不强制套用模板。不确定时先粗分或留待核对，阅读后再调整。
- 已有授权覆盖的归类直接执行，不逐篇询问。允许补充、移除错误归属或调整分类；保留无关的原有归属，避免为了当前项目重整整个主库。
- 本轮碰到的漏分条目一起处理；用户手动导入的文献在下次文献管理时补分。无需后台监听，也不在每次纯证明或 Fact 读取前扫描主库。
- 主题归类、用户阅读状态和原文核验状态分别维护。AI 阅读过不代表用户已读；分类调整不顺带改作者、题名、引用键、标签、笔记或附件。
- 项目 `papers/` 保留书目、阅读记录和对应 Zotero 条目键；有助于导航时补充集合键或集合路径。普通归类无需另建报告、前后快照、哈希清单或审计记录，失败时在现有文献笔记简记待办即可。

## 操作入口

查询、查重、导入和导出优先复用已安装的 Zotero Skill 和可用工具。需要官方本地 API 写入时，统一使用本插件的 [`scripts/zotero_local.py`](../scripts/zotero_local.py)，不要另写每次启动都申请授权的临时脚本。不要把集合管理加入 Fact MCP，也不要改变 `register_zotero_paper.py` 只登记本地附件的职责。

### 跨对话授权（Windows）

`python -B <orpheus-plugin-root>/scripts/zotero_local.py status` 只检查连接与本实例的凭据缓存，不弹窗、不输出密钥。首次需要写入时运行 `authorize`，或直接运行 `request PATCH /api/users/0/items/ITEMKEY --json-file change.json`（JSON 带条目当前版本）。本机运行时按现有约定选择可用 Python，不把缓存版本号或本机路径硬编码进项目。

用户在 Zotero 选择“始终允许”后，脚本将官方返回的可复用密钥保存在当前 Windows 用户的凭据管理器中。所有使用本插件入口的对话、项目和插件版本共享这一授权，按 `Zotero-Server-ID` 隔离；密钥不进入插件包、Git、项目文件、日志、命令参数或环境变量。授权显示名固定为 `Orpheus Zotero`；安全存储不可用时明确报错，不退回明文文件。

后续写入先复用密钥，只有缺失或 API 返回 401 才走官方授权；一次请求最多续授权一次，拒绝、超时、429、版本冲突等不循环申请。并发进程通过本机互斥锁合并首次授权。只选“允许”的一次性密钥不持久化。`forget` 只删除 Orpheus 保存的当前实例密钥；撤销 Zotero 侧授权在 Zotero 设置中操作。新电脑、不同 Windows 用户、不同 Zotero 实例或撤销后可能需要重新授权。非 Windows 暂不提供此持久授权入口；现有 Zotero Skill 的只读与导入能力不受影响。

Zotero 10+ 的最小写入要点：

- 读取 `/api/` 的 `Zotero-Server-ID`，按目标库与父集合定位集合；键和对象版本不能跨实例或库复用。
- 由统一脚本复用或通过 `POST /api/local/authorize` 取得本地授权，并带匹配的 `Zotero-Server-ID` 和授权头。由用户处理首次或失效后的软件授权窗口；不直接输出或提取缓存密钥。
- 按条目当前版本，只更新 `collections`：使用原集合加上新增集合、减去本次确认不合适的集合。采用 `PATCH` 或支持部分更新的批量 `POST`，不以完整 `PUT` 重写书目。集合不存在时按需创建，不按显示名盲目重复创建。接口见[写请求](https://www.zotero.org/support/dev/web_api/v3/write_requests)。
- 依接口返回判断是否成功；批量写每次最多 50 个对象，注意逐项失败。版本冲突时重新读取后调整；授权拒绝、不可写或失败时简记未完成项，继续其他工作，不反复弹窗。

分类不增加独立读回审查；需要时在后续使用中查看和修正。旧环境不支持写入时先保留项目导航，之后再补 Zotero 归属。

正式冷审者仍只读固定候选及其证据，不负责归类。文献归类不改变 Fact 的提交、审查、接纳协议。
